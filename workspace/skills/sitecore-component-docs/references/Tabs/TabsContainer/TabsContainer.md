# TabsContainer Component

## Purpose
Provides the outer shell and tab navigation for a tabbed content area. It manages the active tab state, reads child `TabItem` renderings from the `tabscontainer` placeholder, and renders a row (or column, for vertical layouts) of tab buttons above (or beside) the active panel. In Experience Editor the container renders a descriptive edit-mode notice and lists all child tab items for simultaneous editing. Layout orientation (horizontal, vertical-left, vertical-right) is controlled via the rendering variant exported from the component.

## Fields
**Fields:** None — `TabsContainer` has no datasource fields. All configuration is via the rendering variant (layout) and child `TabItem` renderings.

## Component Variants
| Variant | Export Name | Use Case |
|---------|-------------|----------|
| Default (Horizontal) | `Default` | Tabs displayed as a horizontal row above content |
| Vertical Left | `VerticalLeft` | Tabs displayed as a vertical column to the left of content (on `md+` screens) |
| Vertical Right | `VerticalRight` | Tabs displayed as a vertical column to the right of content (on `md+` screens) |

## Example Content Entry

### Minimum Viable Content
No datasource fields to populate. Place the `TabsContainer` rendering on the page and add at least one `TabItem` to its `tabscontainer` placeholder.

### Full Content Example
```
Page layout:
  TabsContainer (variant: Default)

      TabItem (heading: "Overview",      body: "<p>...</p>")

      TabItem (heading: "Downloads",     body: "<p>...</p>")
```

## MCP Authoring Instructions
To add a `TabsContainer` to a page:
1. Insert the `TabsContainer` rendering onto the page in the desired placeholder.
2. Choose the variant that matches the desired layout:
   - **Default** — tabs as a horizontal row (most common).
   - **VerticalLeft** — tabs as a sidebar to the left (on desktop screens).
   - **VerticalRight** — tabs as a sidebar to the right (on desktop screens).
3. `TabsContainer` has no datasource — do not assign a datasource item.
4. After inserting the container, add one or more **`TabItem`** renderings into the `tabscontainer` placeholder that appears inside it.
5. The first `TabItem` in the placeholder is selected by default on page load.
6. In Experience Editor, an edit-mode notice is displayed and all tabs are visible for editing.
